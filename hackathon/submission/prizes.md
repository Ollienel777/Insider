# Prize evidence

One row per requirement in [`SPEC.md` §3](../SPEC.md#3-prize-requirements),
checked against the code on `main`. The requirement column quotes SPEC §3,
which quotes [`tracks/prizes.md`](../tracks/prizes.md). SPEC §3 also plans
work that is not on `main` yet (casting, Owner Mode); each row says which part
is on `main` and which is still in an open pull request.

**Read this first.** The app runs in fake mode by default, and CI always does:
fixture buildings, a hand-authored floor and recorded model turns. The top
bar's `FIXTURES` chip says so. **Anthropic is the only service run live**, and
only on fixture building F1: the crew and the Security Chief (29 calls,
[`40ebd5a`](https://github.com/Ollienel777/Insider/commit/40ebd5a5fdf0508a51d67a793719a06efd6eac97))
and the Level Builder (two runs on `claude-sonnet-4-6`,
[`dd0d2ae`](https://github.com/Ollienel777/Insider/commit/dd0d2ae2da3145aa3a9436335b3080d6bec74185)),
as the [README](../../README.md#sponsor-technology-and-where-it-lives) records.
The live CoStar, Vexcel, Matterport and Amazon Bedrock paths are written and
unit-tested against stubs, but **none has been run against the real
service**.

**Statuses.** **Met**: true on `main` today, nothing live involved. **Met on
fixtures (live untested)**: true in fake mode; the live data path is written
but has never run. **Partly met**: some of it is true on `main`; the row says
what is missing. **Not met**: not true on `main`; the row says what it needs.
"In progress" means an open issue or pull request, not merged work.

The open questions Q1 to Q9 are in [`SPEC.md` §11](../SPEC.md#11-open-questions)
and on the status issue,
[#1](https://github.com/Ollienel777/Insider/issues/1).
